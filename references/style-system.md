# Стиль-система Reels (каталог элементов)

Разобрано из референс-рилсов говорящих голов. Это переиспользуемая система: любое сырьё
превращается в «такой» ролик набором приёмов ниже.

## ДНК стиля (общий скелет)

1. Вертикаль 9:16, одна **говорящая голова** базой, всё остальное — слои поверх.
2. **Хук-заголовок в первую секунду** — крупный Bebas, акцент **только на 1 слове**
   строчным рукописным Marggraff.
3. **Вшитые karaoke-субтитры** по фразам: единый бело-оранжевый контракт, snappy-смена.
4. **Плавающий b-roll** — карточка/полароид/PiP/телефон-мокап с тенью и наклоном, поп-ин с овершутом.
5. **Split-screen** — спикер сверху + грид вторичного контента снизу (со стат-счётчиками).
6. **Крупные цифры листикла** в негативе (для форматов-списков).
7. **CTA-замок** на выходе («сохрани / подпишись»).

Одно визуальное событие каждые **2–3 секунды**; на хуке — чаще. Базовый кадр стабилизирован
по лицу/голове, склейки hard-cut; важные фразы получают редкие плавные attention zoom.

## Два регистра одного бренда

- **A «Studio Bold»** — продающий/виральный. Жирный гротеск, насыщенный акцент (coral/magenta),
  студийный фон, быстрый темп.
- **B «Quiet Editorial»** — личный/доверительный. Тонкая разрядка-капс, приглушённый грейд,
  плавающие «полароиды», один цветной акцент-символ.

Палитра и шрифты общие, меняется только «громкость». На кадре — максимум **один** насыщенный акцент за раз.

## Каталог элементов (как выглядит + поведение)

### 1. Хук-заголовок
- Хук формулирует самостоятельное обещание/контраст именно этого фрагмента; не повторяет
  дословно title long-form и не вводит внутренний термин, которого нет в речи.
- Хук обязателен, когда первые кадры — экран/инфографика и без контекста непонятно, о чём
  речь. Для ясной talking-head первой фразы его можно не добавлять только с явной пометкой
  `hook_omitted_reason`.
- Зона адаптируется к материалу: не закрывает вебку/лицо/инфографику и проходит platform UI
  safe-zone. Для screen-first approved layout ориентир `x=260, y=340, w=760, h=330`.
- Основная часть: `Bebas Neue Cyrillic`, КАПС. Ровно одно смысловое слово:
  `Marggraff Kursiv Zarte`, только lowercase, coral `#FF6A3D`, без box/pill.
- Вход начинается около `0.42s`, fade-out `2.18–2.38s`, clip заканчивается около `2.6s`;
  анимация seek-safe. Хук не должен спорить с обязательным film-opening и не закрывает
  karaoke-субтитры: на hook-window дублирующие captions выключены.

### 2. Karaoke-субтитры
- Зона: низ-центр (или на шве при split-screen). 1 фраза.
- Вход: snappy поп per-фраза (`back.out`), смена hard-cut.
- Контракт серии: основной текст `Bebas Neue Cyrillic`, `#FFFFFF`; выбранные смысловые
  слова одновременно меняют цвет на `#FF6A3D` **и** шрифт на `Marggraff Kursiv Zarte`.
  Все Marggraff spans только lowercase. Не превращать всю фразу в рукописный/оранжевый текст.
- Approved baseline: main `82px`, letter-spacing `1.1px`; Marggraff ≈`1.18em`,
  baseline-offset `+7px`; `max-width:920px`, максимум две строки. Вертикальная позиция
  выбирается по format profile/platform UI mock, а не слепо хардкодится для всех раскладок.
- Контейнер: **никакой плашки/pill/рамки/border/непрозрачного background**. Текст рисуется
  прямо поверх видео с мягкой тенью.
- Запрет: magenta, yellow и любые другие цвета не используются в субтитрах ни в одном Short.
  Они допустимы в hook, CTA или декоративной графике вне subtitle layer.
- Покрытие: все произнесённые слова непрерывным потоком, кроме участка, где на экране hook
  или CTA намеренно заменяет дублирующий субтитр.
- **Источник — авто, не руками.** Текст и тайминги берутся из звука ролика через
  `references/transcribe_subs.py` (Groq `whisper-large-v3`, пословные тайминги → пофразовая разбивка).
  Акцентное слово (`hl`) выбирается автоматически (самое длинное не-стоп-слово фразы), затем агент
  проверяет семантику и при необходимости правит JSON. См. шаг A5 в `production-pipeline.md`.

### 2a. Face tracking + semantic attention zoom
- Базовый кадр мягко удерживает лицо/голову в безопасной зоне без заметного jitter.
- На важном утверждении: детерминированный zoom-in `1.03–1.08` за `0.7–1.3s`; после payoff —
  плавный zoom-out к базовому масштабу.
- На один Short — `3–5` акцентов, каждый привязан к конкретной фразе/слову транскрипта.
- Не совмещать пик zoom с входом крупного PiP, split-screen, CTA или иной графики,
  перекрывающей лицо. Все тайминги и scale фиксировать в `plan.json`; никакой случайности.

### 3. Плавающая карточка / полароид (PiP-пруф)
- Скрин/клип-доказательство (свой прошлый ролик, статистика). Скругление, **drop-тень**, наклон ±3–6°.
- Вход: поп-ин с овершутом (scale 0.86→1, rotation 8→−4), затем медленный дрейф. 1–2 штуки.
- Зона: **верхний угол над плечом**, не на лице.

### 4. Split-screen (горизонтальный)
- Спикер сверху (~45%), снизу (~55%) — **грид 3×2 вторичного контента** со стат-счётчиками (`👁 76,8 тыс.`).
- Шов — тонкая акцентная линия (magenta) со свечением; субтитр сидит на шве.
- Вход: грид выезжает снизу (`yPercent`), тайлы — стаггер-поп; уход — съезжает вниз.
- Голова спикера **всегда выше шва**.

### 5. Телефон-мокап PiP
- Рамка iPhone (скругление + «чёлка») с контентом внутри. Верхний угол, лёгкий наклон.
- Вход: поп-ин с овершутом и наклоном, дрейф, мягкий уход.

### 6. Полноэкранная b-roll вставка
- Вторичный контент на весь кадр (часто сам поделён надвое). Короткая вставка между склейками.

**Семантика B-ROLL:** это всегда реальный proof media asset — фото, видео, screenshot, UI capture,
слайд или тайл. Текст `overlay`/`note` из storyboard является заданием на подбор и размещение,
а не готовым экранным copy. Не заменять отсутствующий asset текстовой инфографической карточкой.
Если нужен текстовый экран, он должен быть явно помечен `INFOGRAPHIC`/`TEXT_CARD`.

**Proof bank (предпочтительный источник):** сначала искать подходящие собственные опубликованные
фото/видео/screenshots. Для каждого кандидата сохранить локальный путь,
`source_post` (URL или id), `source: owned-media`, OCR-текст/числа, семантическое совпадение с тезисом
и `rights_note`/source notes. Выбирать authentic proof по смыслу, а не просто красивый кадр.
Если совпадение слабое или происхождение/права неясны — asset не использовать. Сток допустим
только когда authentic proof отсутствует и он не выдаётся за доказательство.

### 6a. Исходные вшитые субтитры
- До рендера проверить исходник по кадрам начала/середины/конца на burned-in captions.
- При обнаружении выбрать чистый кроп/перекомпоновку либо закрыть исходный subtitle-region
  проверенным визуальным слоем; новый subtitle layer не должен сосуществовать со старым.
- Если старые титры нельзя подавить без потери лица или доказательства — выбрать другой фрагмент
  или пометить render `blocked`.

### 7. Крупные цифры листикла
- «1.» «2.» … тонким весом в негативе (угол), держатся весь пункт.

### 8. Стат-callout / бейдж-уведомление
- Нативные счётчики (`👁 N тыс.`) на тайлах; pop-in бейдж реакций (❤/💬) на ключевом слове.

### 9. CTA-замок
- Пилюля magenta «сохрани» + серая строка «подпишись…». Смена регистра на строчный.

> Примечание: в одном из референсов «второй слой» был **физическим** (стикеры на доске руками в кадре) —
> это аналоговый приём, не цифровой элемент; цифрового split/PiP там нет. Не всё надо повторять оверлеями.
